## How to read the evidence

- **S**: source or a test implementation was inspected. This proves existence, not execution or correctness.
- **E**: an executed component check is recorded by the cited report. Where only an implementer/parent report exists, it is not called independent.
- **I**: an independent reviewer recorded a passing check for the stated scope and source snapshot. Later edits require recheck.
- **R**: actual runtime evidence. Backend SQLite TestClient/restore, fake IndexedDB, injected transports, in-app browser, installed extension browsers and PostgreSQL are different evidence classes and are never substituted for one another.
- **V**: independently verified within the criterion's bounded core/component scope. It is not release certification.
- **P**: partial evidence, changing implementation, or a required recheck is pending.
- **G**: demonstrated source or test-implementation gap. See the numbered internal gaps below.
- **U**: required external/native/runtime evidence is absent.

Every row has a disposition. Mixed criteria retain their outstanding product/runtime portion even when their component passes. Counts in different reports overlap and must not be added together. This task authored earlier counting/summary work, RCB-01 and the MA01 metadata split. Their independent clearance belongs to the separate reviewers cited here; this documentation audit adds no implementation approval or test execution.

Single-letter evidence keys below identify source collections in the implementation/evidence columns. Disposition letters in the last column describe acceptance status; an evidence key such as U (UI sources) is not itself a runtime pass.
