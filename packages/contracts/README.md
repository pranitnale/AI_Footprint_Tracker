# Numerical observation boundary

The `@footprint/contracts` package exports strict request, attempt and batch Zod schemas, inferred TypeScript types, empty numerical measurement/media constructors, SHA-256 canonical hashing and a sanitized failure catalog. Version 1.1.0 accepts only explicit numerical/categorical metadata. Unknown nested fields, raw content, arbitrary model IDs, invalid Counter strings, counter overflow, invalid dates, contradictory null evidence and unearned calibrated profiles are rejected. Policy semantic versions are independent from client versions and are checked against the tenant's current accepted capture eras by the server.

`src/export-schema.ts` generates JSON Schema artifacts consumed by `python/footprint_contracts.py`. Python supplements JSON Schema with the same numerical maximum, date, unique-list, media-link and null/evidence refinements. Never log a raw Zod/jsonschema exception: it can include a caller's invalid value. API surfaces use the sanitized catalog or `ContractError.code`.

Canonical JSON sorts ASCII contract keys, uses compact UTF-8 JSON, rejects unsafe JSON numbers and limits nesting to 16. Counter/Decimal quantities remain strings. Payload hashes cover only validated numerical records. The trusted ledger alone derives provider HMAC identities; hashing content is prohibited.

Dependencies are Zod 4.6.1 and @noble/hashes 2.4.0, both MIT. Original upstream license texts are preserved in `LICENSES/`. JSON Schema plus refinement parity and Python tests require `jsonschema==4.25.1`; the backend lock records its transitive dependencies.

Version 1.2.0 adds request-scoped `documents.extracted_text` metadata. The generic observation and batch types are strict unions. Explicit `RequestObservationV11/V12`, `AttemptObservationV11/V12`, `ObservationV11/V12` schemas and types preserve historical validation; `UsageBatchV12Schema` permits exact mixed historical records, while `UsageBatchV11Schema` stays 1.1-only. `ExtractedFileTextComponent`, `ExtractedFileTextMeasurement`, `ExtractionProfile` and `FileCoverageReason` are exported. `extractedFileText(request)` is a non-mutating display projection; it never normalizes or rehashes a record. Archived `*-1.1.0.schema.json` validators are frozen and hash-pinned by tests. File text is non-additive and requires separately verified request association. See CONTRACTS section 11.
