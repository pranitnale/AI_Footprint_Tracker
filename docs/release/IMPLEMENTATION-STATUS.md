## Verification procedure

The machine-readable `docs/release/acceptance-evidence.json` records 286 acceptance rows extracted from the normative tables. Statuses remain one narrow arithmetic pass and 285 unverified rows in this reconciliation. Supporting evidence is recorded separately from complete gate closure. Evidence may close only the behavior actually tested; no automatic pass is inferred from a test name or an implementer report.

1. Review actual code and independent-input tests against each contract, including failure and concurrency behavior.
2. Build separate Chrome, Edge and Firefox artifacts and validate their permissions, packaged assets and reproducibility.
3. Run backend integration tests against PostgreSQL, including retries, concurrent identity/roles, privacy markers and erasure/restore.
4. Exercise website routes, controls, copy, keyboard behavior and layouts with the in-app browser and inspect console/network failures.
5. Exercise installable extension behavior and the provider/browser matrix where actual target capabilities and authorized accounts are available. Record unavailable capability separately from a failing product behavior.
6. Run measured workload and host-overhead checks; preserve exact environments and results.
7. Resolve defects and repeat the checks affected by each fix. Report passed, failed, unverified and inapplicable evidence separately.

Release remains unverified until these steps and the normative external gates are fulfilled.
