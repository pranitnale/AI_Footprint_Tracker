# Deployment files

- `compose.yaml` starts PostgreSQL, a one-shot migration, API, maintenance worker and HTTPS web proxy.
- `deploy/proxy/Dockerfile` builds the HTTPS web proxy around the website in `apps/web/dist`. Build that website on the host first with `pnpm --filter @footprint/web build`, after `pnpm package:browsers` and `pnpm verify:source-archive`. The image does not build the website itself, because that build needs the release artifacts and source files that stay outside the Docker build context. It checks each download against the release manifest again and fails if the website is missing or a download changed.
- `deploy/proxy/default.conf.template` serves only known SPA routes and static files, proxies API/auth/health paths, keeps the operator on a separate exact host and returns 404 for unknown hosts and paths. The registration host serves the website, `/register`, `/login` and the `/admin` pages, which is all the hosted service needs.
- Serving rules in both templates (15 October 2026): content-hashed `/assets` files are cached for a year (`immutable`), pages are revalidated on every visit (`no-cache`) and `/downloads` are cached for five minutes, then revalidated. nginx compresses (gzip) the website's text files and only these API answers: the member, organization, administrator, conversation and saved-history summaries, `/v1/admin/breakdown`, `/v1/admin/activity` and `/v1/methods`. They contain usage figures and no session, CSRF value or token. Every other API answer stays uncompressed (`gzip off`), because sign-in, session, connection and refresh answers carry tokens or CSRF values, and compressing a secret together with text a request can choose lets an observer of response sizes guess the secret (BREACH). The summary location also waits 95 s for the API, so the website's and extension's 90 s limit is the one that ends a slow summary. API answers keep their own `Cache-Control: no-store`. nginx keeps its connections to the API open (`keepalive`, no `Connection: close`); uvicorn keeps them for 75 s, longer than nginx's 60 s.
- `apps/server/Dockerfile` runs the API with `WEB_CONCURRENCY=4` uvicorn worker processes. Each process holds at most 12 database connections (`POOL_SIZE` plus `POOL_OVERFLOW` in `apps/server/aift/db.py`), so the API and the maintenance worker use at most 60 of PostgreSQL's default 100. Raise PostgreSQL's `max_connections` before raising the process count or the pool. The request log (`AIFT_REQUEST_LOG`) is one file per UTC day, `requests.log.YYYY-MM-DD`, which every process appends to; files older than 14 days are deleted.
- `deploy/proxy/tenant.conf.template` is the self-hosted organization's own host. `deploy/proxy/10-validate-config.sh` adds it to the nginx templates only when `AIFT_TENANT_HOST` is set, and refuses a tenant host equal to the registration or operator host. A self-hosted organization needs its own domain or subdomain; the hosted service leaves `AIFT_TENANT_HOST` empty.
- `deploy/examples/compose.env.example` contains non-secret path and host examples.
- `deploy/examples/settings.self-hosted.example.json` contains the exact server setting fields with invalid placeholders and all production verification flags false.

Use `docs/operations/SELF-HOSTING.md` for setup, backup, restore and key procedures. The files are ready to configure; they contain no live hostname, certificate, mailbox identity, credential or test flag.
