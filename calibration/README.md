# Reproducibility and remaining validation

The 400-case synthetic supplied-text corpus freezes 300 training cases and 100 holdout cases before comparison. English, German, code, numeric and Unicode groups use different holdout templates. Long text and edge cases include literal special-token strings, empty text, combining characters and emoji. No fitting is performed. Expected counts come from official local `openai/tiktoken` 0.14.0 `encode_ordinary`; the runtime uses pinned `gpt-tokenizer` 4.0.0 with specials treated as ordinary text. There are 800 count comparisons across two encodings. This verifies supplied-text encoding parity only. It does not validate a consumer model mapping, complete capture, hidden reasoning or generated-output/provider usage.

Regenerate deliberately with Python 3.12+ and `tiktoken==0.14.0`: `python calibration/generate-tokenizer-reference.py`. The official reference may retrieve public encoding assets during generation. Ordinary tests use committed expected counts and packaged runtime assets; they perform no provider requests and send no text externally. Do not place employee content in this corpus. Tests require Python `jsonschema==4.25.1` (the server environment also supplies it). Set `PYTHONPATH` to that environment when needed; `.local-calibration-deps` is an ignored development convenience, never a build artifact.

`numeric-fixtures.json` defines 48-digit working precision, round-half-even and 18-place base-unit serialization. TypeScript Decimal and Python Decimal independently calculate the same observations and old/new bundles. Published rounded examples are separate independent checks. Extreme counters, null factors, boundary conversions, scope mismatch, coefficient replacement, equation replacement and historical views are tested. Input length has no explicit coefficient in the accepted output surrogate.

Energy hardware validation is **unverified**: no suitable untouched public measured corpus has been incorporated. Reference arithmetic cannot establish physical accuracy. Claude counting/API validation and Google LocalTokenizer model-specific parity are **unverified**. No maintainer credential, paid generation, hardware experiment or dataset purchase was used. No runtime profile has calibrated status. Promotion requires the methodology quality gates and genuine compatible measurement evidence; a percentage-accuracy badge is prohibited.
