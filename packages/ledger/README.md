# Local ledger

`Ledger.open()` opens IndexedDB version 15. The public `Ledger` class keeps existing callers compatible. New calculation callers use `EstimationRepository` and `CaptureRepository`, without naming object stores or importing IndexedDB types.

## Modules

- `database.ts`: current schema indexes and the preproduction version-15 usage reset.
- `ledger-support.ts`: shared record types, validation, source guards, and transaction helpers.
- `history-repository.ts`: numeric history admission, bounded history reads, and its upload queue.
- `estimation-contracts.ts`: the typed calculation storage boundary and DTOs.
- `estimation-storage.ts`: source indexing, canonical dependency resolution, original envelopes, index setup and erasure helpers.
- `estimation-repository.ts`: installation preferences, durable jobs, result admission and view selection.
- `local-selection.ts`: local read grants, preference validation and coherent publication vectors.
- `original-live.ts`: bounded archived original lookup with immutable source proof.
- `original-method-proof.ts`: indexed proof of one trusted original method across a scope's current inputs.
- `cleanup-recovery.ts`: bounded recovery of durable, already-authorized cleanup markers.
- `repository-contracts.ts`: explicit tracking, observation query, publication, derived state, sync, history, thread and erasure ports.
- `session-contracts.ts`: portable session, method catalog and health state and operations.
- `indexeddb-repository.ts` and `indexeddb-session.ts`: domain adapters over the existing shared ledger transactions.
- `capture-validation.ts`: source checks for checkpoint and current-estimate metadata inside the capture transaction.
- `memory-*.ts`: an independent in-memory backend with shared state and staged atomic mutations.
- `index.ts`: compatibility facade, capture, synchronization, canonical reconciliation and deletion orchestration.

There is one database and one write transaction boundary. History, capture, original results, input invalidation and outboxes commit together. The ledger imports no engine, performs no numerical formulas, and makes no network calls. The package tests may inject an executor or use the real estimator as a fixture producer.

## Storage substitution

Application services accept `ApplicationRepository` or a narrower domain interface. `RepositorySource` also accepts a structural `{application: ApplicationRepository}` provider. `resolveApplicationRepository(source)` resolves that shape without class detection. The compatibility `Ledger.application` getter caches an IndexedDB adapter; production composition can pass it explicitly. `createMemoryRepository()` returns the same domain interface without using IndexedDB, a browser service or a simulated database.

The ports do not accept table/index names or generic key/value commands. Callers use `checkpoint`, `commitCapture`, `scanRequests`, `scanAttempts`, `currentEstimate`, `pendingRevision`, `summaryVersion`, `readSummary`, `findHistoryMessage`, `findHistoryMessages` and `historyCoverage`. Existing guarded domain operations keep their signatures. The batched reads `findHistoryMessages`, `historyRowFlags` and `estimation.resultsFor` accept at most 100 items and answer each item exactly as the single-item read would, in one transaction. `historyCoverage` retains device identity for upload admission. A service can depend only on the interfaces it uses; the full interface groups explicit capabilities from one backend.

`commitCapture` accepts `{scope, observations, checkpoint?, originals?, archivedEstimates?, currentEstimate?, guard?}`. The adapter derives legacy archive and pointer keys. `archivedEstimates` accepts a raw Original result or a full live envelope, and an explicit null current estimate remains null in storage. Observations, checkpoint, originals, current estimate and outbox share one commit. The command is detached before asynchronous work; checkpoint and current-estimate identities are checked against staged observations, including an unchanged attempt during a request-only metadata update.

Session changes use named fields and a guarded `applySessionChanges` operation. Omitted fields remain unchanged and null removes that domain record. Credential, ownership, pending-connection and reconnect changes commit together. Session DTOs omit physical keys. Method catalogs expose `{catalog, revision}`; `methodCatalogDigest` preserves the existing sealed representation while the adapter keeps its storage key private. Callers use the returned revision for compare-and-set admission.

The memory backend accepts optional `now`, `id` and `beforeCommit` dependencies. It serializes mutations, stages changes before publication and clones returned data. The fault hook supports rollback and cancellation checks in tests. It performs no estimation formulas; callers supply the executor. Memory is a substitution and testing backend, not the production default or a durable replacement for IndexedDB.

Shared contract tests run the same capture, rollback, revision/ACK, source guard, erasure, history reimport and calculation cases against both backends. Separate application tests must also exercise actual consumers with memory before architecture acceptance is complete. The prior ledger migration/estimation review and the additive storage-port review are separate snapshots.

## New APIs

All functions below return promises. Full types are in `src/estimation-contracts.ts`.

| Operation                                                    | Contract                                                                                                                                                                                                                                                                                                                                 |
| ------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `capture(scope, observations, originals?)`                   | Validate observations and genuine `EstimationEnvelope` originals, then atomically persist observations, originals, source changes and the appropriate outbox. Existing `commit` also accepts envelope2 in its `local_estimates` metadata, including compatibility `current:` rows.                                                       |
| `estimation.liveInput(scope, attemptId)`                     | Prepare a validated live request/attempt and actual canonical alias binding without creating a job. Missing scoped dependencies return `null`.                                                                                                                                                                                           |
| `estimation.readPreference()`                                | Read the installation's validated preference, or `null` before one is saved. The implicit initial selection revision is 1.                                                                                                                                                                                                               |
| `compareAndSetPreference(expectedRevision, next)`            | Save only if the stored revision matches. `null` expects no saved preference. The supplied next revision must equal `(expectedRevision ?? 0) + 1`. Concurrent losers return `false`; invalid records throw.                                                                                                                              |
| `state(scope)`                                               | Return `{active, selected, pending, publicationVersion}`. Selected includes its exact target identity and selection revision. Pending counts current inputs newer than its published watermark. Wrong ownership or enrollment returns no accessible jobs.                                                                                |
| `start({scope, target, selectionRevision, fallbackMethod?})` | Resume an identical active job or create a new generation. Same-method catch-up processes only inputs beyond the completed watermark; a different target starts a full bounded recalculation. Trusted orchestration supplies an exact original `fallbackMethod` for EcoLogits fallback; result data cannot grant its own child identity. |
| `resume(scope)`                                              | Return only the current valid running job. No executor is started by the ledger.                                                                                                                                                                                                                                                         |
| `page(jobId, limit = 100)`                                   | Return at most 100 inputs, durable unavailable-dependency outcomes, and progress. A live input contains unchanged request and attempt payloads and a validated source binding; history contains its unchanged message. No transaction remains open while the caller calculates.                                                          |
| `commitResult({jobId, inputKey, sequence, result})`          | Validate the envelope, exact input hash, target identity, original lineage, actual source revisions/hashes, alias relation, ownership, erasure and active generation. Return `applied`, `duplicate` or `stale`. Invalid method/results throw.                                                                                            |
| `markUnavailable({jobId, inputKey, sequence, reason})`       | Store a terminal outcome for a missing dependency, integrity failure, missing original implementation, or unsupported method. Use this only for known deterministic absence. Transient executor/storage errors leave work retryable.                                                                                                     |
| `promote(jobId)`                                             | Publish only when every member of the declared snapshot has a persisted result or unavailable outcome. Advance selection and its calculation publication version atomically.                                                                                                                                                             |
| `cancel(jobId)`                                              | Cancel and remove that candidate's results. Cancelling a completed selected view removes its inherited result cache too and supersedes any active same-method job that depended on it. Original observations/results remain.                                                                                                             |
| `resultFor(scope, source, methodHash)`                       | Return a source-current published result for that exact method, or an exact-source original for the same method. It does not implicitly select another method. Check `state` when the caller requires only a completed default view.                                                                                                     |
| `resultsFor(scope, sources, methodHash)`                     | The same answer as `resultFor` for each of at most 100 sources, read in one transaction.                                                                                                                                                                                                                                                 |
| `viewPage({scope, view, after?, limit?})`                    | Return bounded rows with one selected result slot, a separate original for inspection, and a state. `contributes` excludes unavailable sources and verified history/live overlap. Never add the inspection original to the selected result.                                                                                              |

`commitHistory` retains its existing arguments and additionally accepts `expected.envelopes?: Record<messageKey, EstimationEnvelope>`. Improved response rows, their projected resources, envelopes and queues commit atomically. The first admitted method stays pinned. A racing method mismatch throws `method_admission_conflict` before writes, allowing the caller to reload the winning pin and recompute. `checkedHistoryRow` is exported for validated legacy reads. Optional `expected.healthCodes` accepts only `method_unsupported`, `estimate_unavailable`, and `method_update_invalid`; deduplicated namespace health rows commit with accepted records and roll back on any guard or storage failure. A page that writes no record and leaves the readable coverage unchanged (ignoring its observation time and the sync-only pending flag) does not bump the summary version, so reopening an imported chat does not invalidate concurrent reads.

`readPreferenceState()` distinguishes missing, valid and invalid saved choices without returning invalid raw data. `repairPreference(expectedRevision, explicitChoice)` repairs only a still-invalid row with the same sanitized revision. Its new revision exceeds the saved revision, durable job revisions and the persisted revision floor. Concurrent valid choices win; exhausted revisions and failed writes leave the invalid state intact. Repair preserves observations and originals, supersedes unfinished jobs, and advances calculation publication versions.

`localSelectionState(currentAuthorityScope)` returns `execution: "local_only"`, up to 64 scoped members, their current jobs, input/pending counts and publication versions, an unprovable count, an overflow flag and an opaque token. `localSelectionCurrent(scope, token)` checks the same vector. Missing or mismatched authority fails closed. A valid read grant with an invalid preference still permits explicitly Original data; it does not authorize a selected method. Pass `{authorityScope, localSelectionToken}` as the fifth `publicationSnapshot` argument to validate this vector atomically with observation, erasure, routing and thread guards. The returned `calculationCurrent` defaults to true for existing callers without a selection guard. Page progress does not invalidate a published view; source, selection, erasure and trust changes do.

Authorized `state(scope)` results and local-selection members expose `inputCount` and `uniformOriginalMethodHash`. The hash is non-null only when every current input has that exact known original method pin. Mixed and missing pins return null; empty authorized scopes return count zero. Denied states omit the count, and older implementations without proof must be treated as unknown. The proof is part of the publication token. IndexedDB reads one composite index key and an exact bucket count against the scope count, without reading historical source payloads. Memory maintains the equivalent per-scope counts with input mutations. An initial Original-default shortcut is safe only for empty inputs or a uniform hash equal to the requested Original method, in addition to the preference/job checks. It must hold across the whole authorized selection vector.

`originalForLive(currentAuthorityScope, {attemptId, attemptRevision, attemptHash})` returns an original envelope with its archived request and attempt proof. The current attempt must match exactly. Later request revisions and canonical aliases do not rewrite the archived envelope. An exact index lookup reads at most two candidates; a validated compatibility pointer resolves multiple originals. Missing authority, erased/superseded sources and ambiguous candidates return null. Damaged archived evidence throws `ledger_integrity_failed`.

`Ledger.resumePendingCleanup(limit = 32)` resumes only durable cleanup targets, including linked history whose source was already deleted. It validates each marker again after reading its bounded batch and returns `{processed, pending}`. Failed work remains pending for retry. Call it at startup and periodic maintenance; pending cleanup suppresses publication and uploads until physically completed.

`cacheSummary(namespace, key, summary, version, selection?)` accepts the same optional `{authorityScope, localSelectionToken}` guard. It checks that token and the observation version within the cache write transaction, then stores `calculationToken` with the summary. A stale calculation rejects with `aggregate_inconsistent` before replacing the cache. Callers can use a stable summary key and compare the stored token on reads.

`claimMonthlyView({scope, month, timezone, selection, company})` guards monthly notification claims with the selected calculation token and stored timezone. `company` is `{deviceId, deletionEpoch}` in company mode and null in Personal mode. One transaction verifies routing, source/selection/erasure state and timezone before consuming the shared namespace/month claim. It returns `claimed`, `already_claimed`, or `stale`; stale checks consume nothing. Legacy monthly claim methods retain their behavior. Application callers must prepare a successful, current view before claiming and recheck publication before delivery.

Inputs expose `originalMethodState: "recorded" | "not_admitted" | "unavailable"`. Only a live observation with the reserved `unavailable-admission-v1` marker, no existing original pin or result evidence, and that same marker on every retained measurement is `not_admitted`. Its selected local calculation may retain `original_method_hash: null` with `original_method_missing`. Earlier method proposals and legacy null proposals cannot be replaced by a later marker. Missing or contradictory older lineage remains unavailable. The marker identifies admission state and is never a formula or engine.

## Paging and atomic visibility

Each current source has a durable increasing sequence. A new job records a watermark and a cursor. Updating a source moves it past the current snapshot watermark, even if that key was already scanned. It becomes explicitly pending, and any obsolete result is removed in the same transaction as the observation change. The snapshot denominator is adjusted to exclude that changed version.

`page` automatically persists unavailable dependencies. For usable inputs, only `commitResult` or `markUnavailable` records completion. The cursor advances across a contiguous sequence of durable outcomes, so out-of-order workers and a crash between page read and result write cannot skip work. Valid unavailable envelopes count as unavailable while retaining their diagnostics.

Results are keyed by ownership scope, input and target method hash. Method IDs and hashes are bound to their full admitted identity; conflicting metadata is rejected before changing an active or selected job. A same-method incremental generation reuses unchanged results in place. Its new results remain invisible until the selected watermark advances. No full-history copy is required. `snapshotTotal` and `processed` describe the declared job set, which can be an incremental subset. `pending` describes newer inputs, rather than claiming they were part of that completed set.

At most one completed and one candidate generation are retained per scope. Supersession and cancellation remove candidate results. Changing targets removes the previous method cache after promotion. Preference changes, promotion and cancellation advance `state.publicationVersion` in the same transaction. They do not change observation/erasure epochs or recorded-page coverage. Numerical readers bind this calculation version separately. Erasure cancels candidate work and removes affected input results while preserving unchanged completed results; namespace erasure removes everything in that namespace.

Canonical relation hashes bind identities but do not authorize aliases. The repository follows the stored scoped alias chain, rejects missing dependencies/cycles/cross-era targets, and rechecks it before result admission and reads. Attempt payloads keep their originally observed request ID. Alias changes invalidate affected calculation inputs while preserving archived originals. Family erasure follows same-era request and attempt alias chains. Attempt-only aliases are removed without deleting independent source requests or sibling attempts; durable attempt tombstones prevent replay and retain reverse edges for interrupted cleanup.

## Migration, retention and limits

Version 15 deliberately discards preproduction usage, observations, checkpoints, upload queues, method caches and calculated results from older databases. It retains authentication, user settings, ownership history, engine preferences and erasure barriers. Old usage schemas are rejected rather than migrated. Reset and index creation share one atomic upgrade; an aborted upgrade rolls back. Existing connections close on version change, and older clients receive `VersionError`.

Request and range erasure remove corresponding envelopes and cancel unsafe candidate jobs while preserving reusable completed results for surviving sources. Namespace erasure removes all scoped envelopes, derived views and jobs. Existing erasure markers remain. Live age retention continues to preserve the separate historical family. Installation preference survives scope deletion. Personal data never enters a company outbox during connection.

Jobs remain scoped to the observation's exact stored era. Current active ownership and credentials grant local arithmetic over known retained eras in the same namespace, including after a device change. The grant is derived from stored routing metadata and never supplied by the caller. Unproved eras remain explicit partial coverage, and null company eras cannot run. Device, ownership, revocation and trust-key changes invalidate unfinished work. Completed exact-method results can be reused under a renewed local read grant. These grants do not authorize upload, capture, or remote execution, and source eras and hashes never change.

History reimports preserve the first canonical row era. The optional internal `lastImportEra` records the latest import authority separately, so an acknowledged duplicate does not recreate its message queue. Refinements update the existing scoped input; originals retain their original bytes. Upload queues and coverage continue to use the current enrollment and device. Proven live/history overlap is checked across all locally granted eras, so one execution contributes once to the combined view.

History rows can also hold an optional internal `countBasis`: the text length, file text lengths, counting runtime and the numeric counts produced for that message. It never holds text or a hash of text, and it never enters the record, the upload queue or the API. The extension reuses the saved count only when a reimported finished message has the same lengths under the same counting runtime; anything else is counted again. A same-era duplicate whose basis is missing or different gains the new basis without changing its record, hash or the summary version. A conflict keeps the basis of the saved record.

`commitHistory` leaves an unchanged coverage row as it is, so its upload flag and an in-flight receipt stay valid and an unchanged reopen uploads nothing. With `deferCoverage`, used for the non-final batches of a multi-batch import, existing coverage is not rewritten until the final batch, so readers never see a half-updated selection. A first import still writes coverage from its first batch.

Numeric read authority is separate from job admission. A saved Personal namespace with a matching recorded ownership era remains readable when company routing falls back because permission or enrollment is unavailable. This includes archived originals and already completed results. Starting or committing a job still requires the current active ownership grant. Routing/trust changes invalidate the read token; missing saved identity, revoked company scopes, namespace erasure and pending cleanup do not receive a readable token.

## Linked live and historical evidence

`EstimationInput` for a live response can include `history`. Its `source.history_binding` binds the historical message key and numeric payload hash. The immutable live request and attempt remain unchanged. Executors select compatible token evidence and live-first timing; the ledger contains no scientific or token-selection formulas.

One shared matching rule is used by memory and IndexedDB summaries and calculation views. It requires a unique canonical response with the exact provider attempt key, authorized ownership, matching site and conversation, and no ambiguous request/attempt identity or known model disagreement. Perplexity can instead establish the provisional conversation through the same verified entry request key plus answer key. A matched send or edit-and-send response can prove its associated historical prompt; regeneration alone cannot. Competing historical identities do not establish a link.

A changed or erased history record invalidates linked live calculation inputs through the dependency index. Reimported unchanged history is a no-op. Callers must run `mergeHistoryEvidence` before calculating and admitting refined history, so the saved payload and result describe the same preserved evidence. Admission rejects a refinement that would silently discard retained timing. Original live results may bind only the captured evidence and remain archived after history improves the current calculation. Canonical live aliases prefer a complete captured timer and stronger output evidence, with stable chronological and identifier tie breakers.

`originalEvidenceCurrent` is a conservative, persisted proof for the initial Original view. Mutation paths compare the full current source (including canonical request and historical bindings) with admitted original source hashes. IndexedDB reads a composite-index count; memory maintains a count per scope. Neither dashboard state query scans historical payloads. Source, history, alias and ownership changes update the proof and invalidate any changed calculation source. An interrupted purge may leave the proof false until the next source refresh, which safely requires recalculation.

Alias promotion operates independently within each enrollment era, site and conversation. The original method pin is recovered from immutable admitted originals when an alias becomes canonical again. A later revision of an aliased capture may archive its genuine original using its actual source IDs without adding another contribution. Erasure removes those archives with their source family.
