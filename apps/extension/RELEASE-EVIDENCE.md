# Extension implementation evidence

This directory contains buildable development packages. Store publication and live provider/browser acceptance have not been completed. The design canvas, saved comments and research files were preserved.

## Build and runtime boundaries

- WXT packages Chrome and Edge as Manifest V3 with a background service worker and an offscreen document hosting a bundled counting worker.
- Firefox uses Manifest V2 and a background worker. Its manifest omits Chromium `offscreen` and declares optional HTTPS origins and optional built-in organization data categories. Firefox 140 is the declared floor for that consent flow. Chromium 137 is the declared floor for the native cryptographic verification used by erasure instructions. Runtime probes verify the actual counting-host APIs and Ed25519 sign/verify support before enrollment. Declared floors still require actual binary tests.
- No debugger, cookies, history, analytics, external counting service or remote executable code is requested. Company traffic requires explicit origin permission and, on Firefox, the optional data-sharing grant. Personal installations with no enrollment make no company requests.
- Original fetch promises, arguments and returned bodies are preserved. Only cloned measurement branches are cancelled. At most four simultaneous captures are admitted, each with an 8 MiB wire budget; decoder frames are capped at 1 MiB and assembled text fields at 2 MiB. The background text queue has a separate 16 MiB cap. These are enforced queue/wire limits, not a claim that total browser heap equals those values.
- The observer handles the observed fetch and ChatGPT WebSocket routes. XHR, dedicated-worker dispatches and sockets created before observer attachment are not asserted as covered. Unknown structures and missed capture have visible diagnostics.

## Executed offline evidence

Tests live in `packages/capture-core/test`, `packages/adapters/test`, `packages/ledger/test` and `apps/extension/test`. They cover Unicode framing, private delta inheritance, selected-candidate ambiguity, tools versus answer text, catchup duplication, preserved fetch identity/bytes, clone admission/cancellation, bfcache restoration, local ownership during enrollment changes, IndexedDB rollback/restart/revisions, strict payload-hash acknowledgements, partial ACKs, explicit unknown quantities, signed erasure verification, context thresholds and bounded all-time aggregation.

The large-history test inserts 10,050 request families (20,100 observations) into fake-indexeddb. Its observed run used pages of at most 200 rows, took 4,998 ms for a cold scan and 0.38 ms for a cached read. At most 16 summary snapshots plus an epoch counter are retained per namespace. Cache epochs reject scans raced by writes. A prior valid snapshot is dated and labeled rebuilding while refresh runs. These timings are Node/fake-indexeddb evidence, not actual browser or extension-on/off performance measurements.

Run from the repository root:

```powershell
pnpm --filter @footprint/capture-core test
pnpm --filter @footprint/adapters test
pnpm --filter @footprint/ledger test
pnpm --filter @footprint/extension test
pnpm --filter @footprint/extension typecheck
pnpm --filter @footprint/extension zip:chrome
pnpm --filter @footprint/extension zip:edge
pnpm --filter @footprint/extension zip:firefox
```

## Context basis

The dated consumer-app catalog documents paid Claude.ai full windows of 1,000,000 or 500,000 tokens for specifically named models. The packaged advisory profiles use half that reference as an engineering planning allowance. This fraction is not a measured output reservation, a proven lower bound or an environmental-saving threshold. Account/plan applicability and actual occupied context remain unverified. Details retains the full reference, source, date/version and caveat. Verified matching consumer/application capacity takes precedence in the selection interface; user-set advisory budgets remain explicitly user-set. Opaque or unmatched models without a basis show guidance unavailable.

The warning state follows a stable branch/model/budget key. Ordinary sends inherit the branch; regeneration/edit forks receive a new identity. Advice triggers strictly above 50%, has an 80% state, rearms at or below 45% subject to 24 hours, and supports local dismissal and snooze. No host action is intercepted or initiated.

## Remaining release evidence

The isolated content script checks the page hook through a nonce-scoped readiness probe. It also correlates trusted plain-Enter, native form-submit and narrowly labeled send-button gestures with a new visible stop-generation indicator. A missing hook reports after 10 seconds; a send plus generation activity without a captured dispatch reports after 15 seconds. Checks never inspect message text, prevent a host action, move focus or mint a usage record. Paused and revoked site access suppress this diagnosis. These DOM signals are deliberately bounded: a provider that changes both its transport and all generation indicators may still need a manual report. Readiness alone does not prove complete provider-mode coverage. Tests exercise suppressed hooks, changed-endpoint activity, normal capture, inactivity and IME/modified keys.

The compact bar includes requests, input/output tokens, electricity, carbon with its gas unit, water and separate status. Server summary snapshots are bounded and scoped by company namespace, My usage versus Company, filters, timezone and deletion epoch. Offline snapshots carry their original cache date and remain separate from current-profile local totals. Deletion clears them before family scanning, and an in-progress erasure blocks cache publication and reads. An atomic namespace/month marker limits the user-opened monthly summary to one panel per month.

Only ChatGPT and Claude currently have verified route-to-conversation lookup for reopening local recorded totals. Gemini and Perplexity retain profile totals but explicitly disclose unavailable reopened-conversation lookup until matching route and transport identity evidence is obtained.

The precise missing Gemini evidence is a sanitized visible pathname paired with the same synthetic conversation's response `[1][0]` and follow-up request `[2][0]`, plus reopening/navigation behavior. The September 9 audit establishes the transport tuple only, with invented IDs that contain no route encoding. Perplexity needs a paired synthetic pathname and a stable conversation/thread field proved across its initial request, follow-up and reopened page. The saved evidence names `frontend_uuid` and `last_backend_uuid` but does not establish either as a stable conversation route ID. The adapter therefore does not promote undocumented `conversation_uuid`, `thread_uuid` or `frontend_context_uuid` aliases. No route scheme was inferred from product familiarity.

Additional source checks retain the observed ChatGPT image count across duplicate metadata updates, allow an unknown dimension to become known without adding an image, and reject missing generation identities or contradictory reported dimensions. Multiple alternative final assistant messages require selection evidence; they are not concatenated into one answer. A `finished_partial` label without a confirmed client-stop reason does not establish normal completion.

The observed tool-role multimodal message with `ghostrider.status=intermediate` now establishes provisional image execution before any asset is delivered. Its message-scoped provisional identity is replaced when the same message provides generation/asset metadata. A confirmed stop during this stage preserves cancelled execution, with requested/returned image count and image energy unavailable. Neither the dynamic tool name nor an ordinary empty text message establishes that image operation.

Company conversation displays request their own canonical `/v1/me/conversations/{opaque-key}/summary` snapshot, including on supported route reopen. The current-profile summary and latest outbox revisions are separately labeled; pending revisions can replace older server observations and are never added to the whole server total. Capture sends its local snapshot first and refreshes the canonical snapshot asynchronously, sharing a conversation fetch and bounding outstanding display jobs to 16. Streaming refreshes reuse a dated cache for at most 10 seconds; terminal synchronization requests another snapshot. Namespace/permission changes discard stale company displays, and erasure/auth failures cannot recover a cached server total. This source behavior has synthetic transport/IndexedDB tests, not installed-browser acceptance.

## Native installation handoff

The normal development builds remain `.output/chrome-mv3`, `.output/edge-mv3` and `.output/firefox-mv2` inside this extension directory. Rebuild the same directory after source changes and use the browser's Reload action. Chrome and Edge derive an unpacked extension ID from the directory path. Pointing an existing installation at a suffixed browser/default variant can therefore create a separate extension with separate local storage, and must not be presented as an in-place upgrade or a migration of local numeric history. Use Advanced settings to change the engine in the existing installation. The six suffixed variant folders are separate release and side-by-side QA outputs.

A Chromium test loads its matching directory through that browser's native extension manager in developer mode. A Firefox temporary test loads the generated `manifest.json` through its native add-on debugging page; that is a development session, not signed store installation. No browser-security or signature setting needs to be disabled.

The current Codex in-app surface has no exposed extension-install operation in this session. DOM/Network CDP access alone does not establish support for loading an extension, opening a browser-native file chooser or inspecting a service worker. When that installation capability is unavailable, the project permits the official Chrome CUA surface as a capability fallback. The browser owner must verify that surface's actual extension-manager/file-selection support; if it cannot select the local directory, the user can perform that native selection and the approved surface can continue ordinary UI checks. Do not launch another driver, install a separate DevTools MCP or bypass a denied internal URL. Edge and Firefox require their own native installation and supported inspection surfaces; a Chrome or in-app pass cannot substitute for either.

Actual target-browser installation, offscreen/background lifecycle, Firefox built-in consent validation, all provider light/dark composer placements, keyboard/contrast/narrow rendering, stopped/retried/history/media flows, extension-on/off transport equivalence and CPU/memory/latency measurements remain required. Image/upload fixture gaps are substantive support gaps, not a completed acceptance checkbox. Signed store packages, current provider-mode rechecks and publication need their own authorized release work.
