# Shared estimate interface

**Current product method: EcoLogits.** The Original estimator documented below is [archived research](../../docs/research/archive/original-method/README.md), retained in place for reproducibility, explicit comparisons and saved-record compatibility. Current product configuration excludes it from engine selection and automatic fallback. Original recorded results are preserved and may themselves have been calculated with EcoLogits.

`estimateAttempt(observation, {methodId?, view?, originalMethodHash?, originalMethodMissing?})` returns immutable numerical metrics, units, selection/cohort/scenario hashes, source provenance, exclusions and original/recalculated lineage. The Python server imports `estimate_observation` from `python/footprint_estimator.py`. Both validate the current observation schema `2.0.0`. Unknown executable methods fail explicitly, while valid observations can remain stored for later compatible calculation.

The application executor accepts a live request/attempt with optional proven linked history, or a historical response on its own. `@footprint/contracts` observation-evidence helpers select compatible output-token evidence and live-then-historical timing; `engines/inputs.ts` binds the sources into the calculation hash. EcoLogits receives the selected duration through the unchanged upstream latency cap, or null for modeled timing. The Original engine's equations remain unchanged and ignore timing numerically. Its optional internal linked-evidence argument supplies the selected token measurement while retaining the original live observation hash; the surrounding engine envelope binds the historical source too.

Each equation is a pure module under `src/methods`. `data/baseline.json` is an explicitly assembled rough operational reference based on the pinned research registry, not an import of every research entry. It preserves 48-digit Decimal calculation and 18-decimal base-unit serialization. An updated coefficient requires a new method ID. Conflicting values under an existing ID are rejected. Bundles contain data only; no formula strings or remote code are executed. Authenticated data updates use ECDSA P-256 signatures through `installSignedMethodUpdate`; the trust key must come from packaged configuration or authenticated enrollment. Packaged executable releases add new equation IDs.

The baseline uses all four approved reference candidates on the same observation and scenario. It retains the complete electricity winner vector and actual observed model separately. Token counts and unknown hidden work remain separate from rough energy. A zero returned-output count after execution never proves zero electricity. The Original method does not estimate images. Until 20 October 2026 it attached GPU reference figures from the ML.ENERGY Leaderboard to image operations, outside the totals; that data was removed because its source has no licence, so `image_references` is now always empty. Generated images are estimated by the EcoLogits method instead.

Environmental provenance preserves the known OWID lifecycle CO2e and WRI all-source (including seawater) source families. Exact pinned factor vintages and direct-water source category remain unresolved. The Original engine returns direct and upstream water separately with a null total. EcoLogits policy `upstream-wcf-1` instead displays the unchanged upstream WCF as water consumption, with no component recalculations. Its component fields remain null and not applicable for the shared result shape. The new policy changes the method hash; saved original results remain untouched. Published historical arithmetic remains reproducible, but an unresolved denominator/category cannot become a complete product total.

The bundle's `release_validation: pending` is deliberate. It records an implementation review for source fidelity and functional arithmetic, not owner/physical calibration approval. Browser noninterference, live capture and production distribution remain separate release gates. Original views remain reproducible; a recalculated view requires the original method hash except for the explicit unavailable-admission case below. The bounded numerical LRU cache keys include complete observation, method hash and view.

## Recalculating an observation admitted without a method

`EstimationOptions.originalMethodMissing?: boolean` and the same raw `EstimateOptions` flag provide a metadata-only exception. The flag is strictly boolean. It is accepted only for a validated live attempt with `proposed_method_id === UNAVAILABLE_ADMISSION_METHOD_ID` (`unavailable-admission-v1`), an explicit supported target `methodId`, `view: "recalculated"`, and no prior method hash. Supplying both the flag and a known hash is contradictory and rejected. A known hash on an ordinary observation remains unchanged.

The marker is never a formula or registered bundle. Marker observations cannot produce original-view results, even with an explicit supported target, and cannot bypass the flag. Ordinary legacy null-proposed observations keep their former baseline behavior. Arbitrary unknown/retired method IDs, missing archive data and historical sources cannot use this exception.

The new result honestly retains `view: "recalculated"` and `original_method_hash: null`. Wrapper reasons include `original_method_missing`. Original-engine raw output, including original fallback, carries the same view/null lineage and appends that reason to its raw/metric reasons. EcoLogits raw scientific output remains unmodified. No previous hash is fabricated, no saved original is relabeled, and no equation, coefficient or ordinary/frozen result changes.

The caller must separately establish `originalMethodState: "not_admitted"` from its authoritative ledger state and enforce read/publication grants. The executor's marker check does not authorize downgrading a saved known lineage. The future remote boundary derives an `accepted.original_method_missing` boolean locally from this same gate; it never trusts a response to invent the exception. Response reasons and raw Original view/hash metadata must match the accepted binding. No remote endpoint is activated by this option.

## Dormant remote retry and fallback contract

`src/engines/remote-admission.ts` implements retry, deadlines and exact-method fallback behind an injected transport, exercised by fake tests. Production integration remains future work: it adds no production caller, endpoint, authentication handling, remote setting or network permission. A future session adapter must first establish organization capability and authorization, then supply the accepted organization/installation correlation and `isCurrent` guard. Personal mode rejects before transport or fallback. Its executor destination remains `organization`, including when a compatible local fallback is configured; it does not acquire local-only grants.

The transport returns the existing response envelope or throws `RemoteTransportFailure` with `{kind: "offline"}`, `{kind: "timeout"}`, or `{kind: "http", status, retryAfterMs?}`. The adapter translates HTTP `Retry-After` into a validated nonnegative millisecond value. Credentials, headers, response bodies and arbitrary error messages do not enter typed diagnostics. Unexpected transport rejections become `transport_failed`. Received-response validation is separate: serialization/getter exceptions become `response_invalid` and cannot initiate retry or local fallback, even if an injected object throws a transport-like error.

Optional `retry` settings are snapshotted at construction. Defaults are three total attempts, a 10-second deadline per attempt, 250 milliseconds initial backoff and a 5-second maximum delay. The schema permits at most four attempts, deadlines up to 60 seconds and maximum delays up to 60 seconds. Exponential delays are capped by that configured maximum. A server delay longer than the maximum ends the operation with its typed failure; the client never retries earlier than that requested delay. Tests inject `clock.sleep(milliseconds, signal)` and advance deadlines/backoff explicitly without real network calls.

Every retry sends the same frozen request, including its operation ID, source revisions, method identities and input hash. A timeout means remote completion is unknown. It never creates another AI request or an extra contribution. The future server must bind idempotency to that operation and its full accepted request. This helper returns one accepted result and ignores late alternatives; its caller persists one authority for each observation/method/view. At most two physical transport/fallback promises may remain unsettled per executor, with no waiting queue. Cancellation and deadlines signal abort, but a promise that ignores cancellation retains its slot until it settles. Further work fails with `busy` instead of accumulating an unbounded queue.

| Transport outcome | Typed failure and recovery |
| --- | --- |
| 401 | `session_expired`; let the session module authenticate again. |
| 403 | `forbidden`; stop and resolve authorization or enrollment. |
| 409 | `conflict`; acquire a fresh accepted scope/revision/method binding. |
| 413 | `payload_too_large`; reduce the submitted scope through a separately authorized operation. |
| 422 | `invalid_input`; correct the numerical input before resubmission. |
| 429 | `rate_limited`; bounded retry with backoff/Retry-After, then retain pending work. |
| 5xx | `server_unavailable`; bounded retry, then retry later with observations intact. |
| Timeout | `timeout`; idempotent bounded retry, then retain the unknown-completion state. |
| Offline | Use the explicit exact local fallback below, otherwise `local_method_unavailable` and retain the pending resource estimate. |
| Cancellation, stale binding or capacity | `cancelled`, `stale` or `busy`; do not publish a result under the old authority. |

`localFallback: {method, executor}` is an explicit opt-in for an offline transport failure only. The declared full method identity must equal the accepted requested method, including implementation, catalog, profile and environment hashes, and the injected executor must declare local execution. Its result must also match the accepted effective child method, selected profile, input/source identity, view and original lineage. A matching method name alone is insufficient. The accepted fallback result retains `execution_origin: "local"`. No fallback follows an HTTP error, timeout exhaustion, rejected result, stale scope or cancellation, and the other formula is never substituted silently. Failure leaves the saved numerical observation intact for its caller to display as pending/unavailable.

Current-scope and cancellation checks run before each transport/fallback call, after awaits and before returning a result. A late local or remote result cannot publish after a selection, source, scope or erasure change. The fake tests cover timeouts after possible completion, status handling, retry limits, exact-method and missing-lineage fallback, cancellation during backoff/fallback, and unsettled-operation limits.
