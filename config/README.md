# Estimation configuration

`estimation.build.json` selects EcoLogits as the default and only available product engine. Standard and controlled browser builds reject the archived Original default. Existing Original preferences migrate to `build_default` with a new selection revision; saved observations and results remain intact. The shared schema still reads historical dual-engine configurations for research and compatibility. Invalid configuration must fail the build.

The EcoLogits fallback policy (`pro-reasoning-2026-10-14`) names one family benchmark per provider: OpenAI `gpt-6.1-sol`, Anthropic `claude-opus-5-5` and Google `gemini-3.8-flash`. A model whose provider is unknown uses `gpt-6.1-sol` (`unknown_provider`). These are developer-selected proxies, not measured upper bounds or inferred parameters for a new model. `model_overrides` takes precedence over a direct binding, and each override records why it stands in for the model (`basis`): `nearest_record` for a named model without its own catalog record (for example an older or pro variant), `family_benchmark` for a named model whose vendor has no catalog record, `model_not_named` when the site does not name the model (automatic routes, research and agent modes, ChatGPT voice, NotebookLM), `model_family_stand_in` for an unknown version of a named model family, `model_variant_stand_in` and `model_kind_stand_in` for an unknown variant (below), and `model_not_in_library` for labels the registry does not list yet that name no family. Details shows the basis and the record used.

Owner decision of 13 October 2026, replacing the provider-flagship rule of 16 September: an unknown version of a named family uses the highest version of that family in the EcoLogits catalog, not the provider benchmark. The families are Claude Haiku, Sonnet, Opus and Fable; GPT Sol, Astra, Luna and Terra; Gemini Flash, Flash-Lite (kept apart from Flash) and Pro. Each has one registry id per site that names such models (`claude-haiku-unlisted`, `chatgpt-gpt-sol-unlisted`, `gemini-flash-lite-unlisted`, `perplexity-claude-haiku-unlisted` and so on), listed with its catalog name pattern in `packages/estimator/src/family-stand-ins.ts`. Their overrides in `estimation.build.json` are generated from `packages/ecologits-core/data/catalog.json` by `corepack pnpm estimation:family-stand-ins`; do not edit them by hand. The estimator test `family-stand-ins.test.ts` fails when the catalog gives a different stand-in, so after adopting an EcoLogits release run the command, review the change and give the policy a new `policy_version`. With EcoLogits 0.11.2 the stand-ins are `claude-haiku-4-5`, `claude-sonnet-5-5`, `claude-opus-5-5`, `claude-fable-5-1`, `gpt-6.1-sol`, `gpt-6-astra`, `gpt-6-luna`, `gpt-5.6-terra`, `gemini-3.8-flash`, `gemini-3.5-flash-lite` and `gemini-3.1-pro-preview`. Before this rule an unknown Claude Haiku 5.5 was estimated as Claude Opus 5.5: for 19,724 output tokens about 89 Wh instead of about 2.2 Wh at the modelled midpoint. The legacy `original_engine` rule remains readable for archived research configurations and saved method definitions; do not enable it in the current product configuration. All references are validated against the pinned catalog during method admission.

Owner decision of 14 October 2026, replacing the rule that left such labels unlisted: an unknown variant, a label with one variant word after the version (with or without a family name), uses the same variant of the highest version in the catalog (`model_variant_stand_in`), or the highest model of the same kind and vendor when the catalog has no version of that variant (`model_kind_stand_in`). A stand-in is never of another vendor. The variants, their registry ids and catalog name patterns are `MODEL_VARIANTS` in `packages/estimator/src/family-stand-ins.ts`, generated by the same command. With EcoLogits 0.11.2: GPT Pro without a family name uses `gpt-5.5-pro`, GPT mini `gpt-5.4-mini`, GPT nano `gpt-5.4-nano` and GPT Codex `gpt-5.3-codex` (one id per variant for every GPT family, as the catalog has these variants only without a family name); a Claude mini, nano or lite variant uses `claude-haiku-4-5` by kind, as Anthropic's records have no small variant; Gemini Pro Image uses `gemini-3-pro-image-preview`, Gemini Flash Image `gemini-3.1-flash-image-preview`, and an image model without a Pro or Flash size (Flash-Lite Image, a new Nano Banana) the newest image record, `gemini-3.1-flash-image-preview`, by kind. Owner correction of 14 October 2026: a Pro after a GPT family name is not a variant but the family model with Pro reasoning ("gpt-6-sol-pro is not a different underlying model from GPT-6 Sol. It is GPT-6 Sol running with reasoning.mode set to pro"). Its ids (`chatgpt-gpt-6-sol-pro`, `perplexity-gpt-6-astra-pro`) are direct bindings in `estimation.mappings.json` to the family model's record, and an unlisted version's id (`chatgpt-gpt-sol-pro-unlisted`) shares the family's stand-in. OpenAI describes GPT-6 Pro in ChatGPT as GPT-6 Astra through the Pro reasoning option, so `chatgpt-gpt-6-pro` binds to `gpt-6-astra`, and an unlisted GPT-6.x Pro uses the Astra family stand-in; `chatgpt-gpt-5-6-sol-pro` (GPT-5.6 Pro) binds to `gpt-5.6-sol`. Only a GPT Pro of a generation without a known family (`gpt-7-pro`) uses `gpt-5.5-pro`, and a family-named Pro record never counts as a GPT Pro. No reasoning multiplier is applied: the extra reasoning output is counted as far as the site shows it. `o3-pro` keeps the `gpt-6-astra` proxy. OpenAI and Claude image models, a Claude Pro, two variant words, an unknown word or an unknown family keep the site's unlisted id and the provider benchmark.

Owner decisions of 14 October 2026 (afternoon): a reasoning or speed word is a setting, not a different model. The extension removes it before any lookup, family or variant check and estimates the base model: its own record when listed, the family stand-in otherwise. Only words seen in labels, fixtures or code are removed: ChatGPT `-instant`, `-thinking`, `-auto-thinking` and `-high` (as in `o3-mini-high`); Claude `-fast` and `-thinking` (`claude-haiku-6-thinking` uses `claude-haiku-4-5` as `claude-haiku-unlisted`); Gemini "Thinking" and "Extended thinking" after a model ("3.8 Flash Thinking" is 3.8 Flash; a version with only "Thinking" is that version's Flash, as the listed "3.6 Thinking" is); Perplexity `_thinking`, `thinking`, `nonthinking`, `reasoning`, `nonreasoning`, `instant`, `_low`, `_medium`, `_high`, `_low_thinking` and, on every id since this decision, `_fast` (`gpt6_sol_fast` is GPT-6 Sol). A label or id the tables list keeps its own entry, so models whose name contains such a word stay distinct (`veo3_fast`, the Computer orchestrators `opus_thinking` and `sonnet_thinking`, `gemini-3-6-thinking`); the catalog has no text record named for a reasoning mode. Nano Banana Pro is Gemini 3 Pro Image: `gemini-nano-banana-pro` and `perplexity-nano-banana-pro` are direct bindings in `estimation.mappings.json` to `google_genai/gemini-3-pro-image-preview`, the record that the "Gemini 3 Pro Image" labels use as a variant stand-in, and the image method credits both ids to Google. `o3-pro` keeps `gpt-6-astra` (`nearest_record`; the catalog has no o3), and Details names it "o3 (Pro reasoning)". Perplexity Best keeps `gpt-6.1-sol` with basis `model_not_named`, and Details says that Perplexity chose the model and did not say which one.

Site labels are normalized to the registry identifiers in `packages/contracts/src/model-ids.ts` by the extension. A label the registry does not list becomes its family's or variant's unlisted id and uses that stand-in, or `<site>-unlisted` with the provider benchmark when it names neither; the raw label stays in the browser and is shown only in Details. Perplexity is a multi-vendor router, so it has no provider default. Its named models use direct consumer-to-API mappings where the catalog has the record, and stand-ins otherwise. Unnamed routes, including the automatic Best route, research, study, Comet and file creation, use `gpt-6.1-sol` with basis `model_not_named`. Models whose vendor has no catalog record (DeepSeek, Grok, Kimi, Nemotron, Qwen, Sonar) use `gpt-6.1-sol` with basis `family_benchmark`. Unlisted Perplexity labels that name a family (`claude55haiku`, `gemini40flash`, `gpt6_2_sol`) use that family's stand-in, labels that name a variant (`gpt7pro`, `gemini3proimage`, `claude60sonnetmini`) that variant's, and a GPT family with Pro reasoning (`gpt6_sol_pro`, `pplx_asi_astra_pro`) the family model's Pro reasoning id. Other Claude labels use `claude-opus-5-5`, other Gemini labels `gemini-3.8-flash`, and the rest the unknown-provider benchmark. GLM 5.2 and 5.3 use the catalog records `zai-glm-5-2` and `zai-glm-5-3` (744B total, 40B active parameters; the catalog files them under Mistral), with US data-centre factors instead of Mistral's Swedish ones (owner decision of 15 October 2026, `environment_overrides` in `estimation.media.json`): the United States electricity mix, PUE 1.09 to 1.14 and WUE 0.13 to 0.99 L/kWh, EcoLogits 0.11.2's own US multi-cloud profile (its `huggingface_hub` provider configuration in `ecologits/tracers/utils.py` and `provider_configurations` of the generated catalog). Perplexity names `perplexity/glm-5.3` as a model it serves in its Agent API and says it hosts open models on US servers, and a press report places GLM 5.2 on Nvidia B200 GPUs in the US; the operator is not public. GLM 5.2 uses `zai-glm-5-2` rather than `glm-5-2`, whose serving speed was measured on Mistral's platform, so both versions use modelled serving speed. NotebookLM names no model and uses `gemini-3-flash-preview`. The EcoLogits policy never falls back to the original engine: the original method is archived and is not selectable in the product. Set a rule to `unavailable` when an unmapped label should produce no estimate instead.

`estimation.media.json` holds the reviewed data of the media methods, which the estimator binds into the method identity:

- Image generation: 2.907 Wh of IT energy per image, the mean reported by Luccioni, Jernite and Strubell (2024), multiplied by the provider's data-centre factors. The image model's vendor decides the provider where the model is named, otherwise the site's provider.
- Speech: audio tokens are the length in seconds times the vendor's rate (OpenAI 20 per second, Anthropic uses OpenAI's, Google 25), estimated with the EcoLogits `gpt-4o-mini-tts` record under the site provider's data-centre factors. Without an audio length, the length is the text's characters divided by 17 per second.
- Video: the EcoLogits 0.11 video method. A size, length or audio setting the page does not show comes from the site defaults (Perplexity 1280 × 720, 8 s, no audio; Gemini 1280 × 720, 10 s, with audio). The Veo model defaults apply only on a site without site defaults, which no current site is. A video without a named model uses the site's stand-in.
- NotebookLM Video Overview: one illustration per 10 s of video, rounded up, each estimated like a generated image, plus the narration as speech.
- Environment overrides by model identifier: an electricity mix zone, and optionally a PUE and a WUE as one decimal or a `min`/`max` range in the shape of EcoLogits' provider configurations. Given factors replace the provider's for that model only; PUE cannot be below 1.
- Claude token factor (`claude_token_factor`, owner decision of 15 October 2026): every count of Claude text the tracker makes with its `o200k-base-4.0.0-reference` tokenizer is multiplied by `factor` (1.56), rounded half up for each counted part, with totals adding the rounded parts. It was measured on `measured_on` with Anthropic's token-counting endpoint (`source`) on `calibration/tokenizer-golden.json`, less the 8 tokens Anthropic adds to every message; Claude Sonnet 5.5, Opus 5.5, Haiku 5.5 and Fable 5.1 counted identically. Claude text means every message on claude.ai and in Claude Cowork and a Perplexity message whose registry id is `perplexity-claude-*` or `perplexity-unlisted-anthropic` (`claudeText` in `packages/contracts/src/claude-tokens.ts`, mirrored by `claude_text` in `footprint_contracts.py`). Counts a provider reports and other tokenizer profiles are never changed. The estimator applies the factor of the method it runs, so a method saved without the field keeps the tokenizer's count; token figures in the extension and on the server always use the packaged factor. Stored counts are never rewritten.

`estimation.mappings.json` contains separately versioned consumer-to-API assumptions. A recognized consumer name is not proof of its hardware, deployment or API equivalence. These mappings select upstream reference data and keep the uncertainty visible. They do not change provider extraction or tokenizer exactness. Upstream import tooling must preserve this file and report missing references rather than overwrite local choices.

New upstream models enter the generated EcoLogits catalog. Add a consumer binding only when appropriate to the observation evidence. A valid direct binding is used before a provider fallback, unless an explicit model override applies. Changing policy, mappings or media data creates a new method identity and a recalculated view; original results remain unchanged.

The runtime, build commands, Advanced settings, update tooling and Python server integration are tracked in [the refinement status](../docs/release/MODULAR-REFINEMENT-STATUS.md). Configuration files alone do not establish complete integration or release readiness.
