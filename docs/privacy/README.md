# Privacy guide

This guide summarizes the implemented privacy boundaries. The published [privacy policy](../../apps/web/src/site/pages/WebPrivacyPolicy.tsx) (`/privacy-policy` on the website) and [data processing agreement](../../apps/web/src/site/pages/WebDPA.tsx) (`/dpa`) are what people and organizations rely on. The technical rules are defined by [`CONTRACTS.md`](../implementation/CONTRACTS.md) and the [product and enrollment specification](../implementation/PRODUCT-AND-ENROLLMENT-SPEC.md). Where this guide and the published policy differ, the policy and the code are right and this guide needs fixing.

## Personal and connected use

Personal mode stores numerical records in the current browser profile. Nothing reaches the service or an organization. The extension contacts only the AI site in use, to read the person's own chat from that site. When a site shows an opened chat without loading all of it, the extension asks that site once for the missing messages, read-only and with the person's sign-in there; this is the setting "Load full chat history automatically", on by default, which can be turned off for all sites or for each site (ChatGPT, Claude, Claude Cowork, Gemini, Perplexity, NotebookLM) in Settings. With it off the extension asks that site for nothing and counts what the site loads on its own, so some older messages may not be counted. Opening the organization side of the dashboard does not contact a server until the person starts a connection.

Nothing new is captured, counted, recorded, read from a site or uploaded before the person agrees (owner decisions of 17 and 18 October 2026). The welcome page opens after installation, and once after an update for installations from before this step; until the person selects Agree and start there or in the popup, the background refuses every tracking message, the content script passes nothing the page observed on, and the bar shows only "Tracking is off" with Set up. The agreement (agreed, the version of the text and the time) is kept in the browser's settings record only. Turn off tracking in Settings withdraws it at once; records already saved stay until the person erases them. Before the agreement and after a withdrawal, the extension may still recalculate the estimates of records already saved in the browser (for example records from a version before this step); this runs locally and sends nothing. Pause is separate and keeps the agreement. Erase local records is separate too: it works with or without the agreement and leaves the agreement as it was, so it never turns tracking on and never asks again (review of 18 October 2026, `tracking-consent.test.ts`). While tracking is off, Sync now applies erasures only and says that nothing was sent. See `apps/extension/lib/tracking-consent.ts`.

After an approved organization connection, records go to that organization's server: the hosted service or the organization's own server. Records saved in the browser before connecting stay in the browser and are not uploaded. For chats opened after connecting, the extension also sends numerical records of their earlier messages with the messages' own dates, so these records can date from before the person joined. The confirmation step names the organization, shows the server address for an organization that runs its own server, and lists what is shared, what is never shared and what stays in the browser. Connect stays off until the person ticks a separate agreement to share this browser's AI use with that organization; the extension keeps that agreement with the version of the dialog's text, the time and the server.

## Data boundaries

The product records numerical observations and allowed operational metadata. It does not store prompt or answer text, thinking text, file contents, file names, chat titles, the provider's own chat or message ids, passwords, cookies or sign-in tokens as usage records. The server's data schema rejects chat text.

Members of one organization can see the same prompt or reply, for example on a shared provider account. So that it counts once in organization totals, a connected browser sends a company key beside each record it can name: a keyed hash (HMAC-SHA256) of the provider's own prompt or reply id under a random key the organization server hands out to its members. The provider's id never leaves the browser, and the key is not part of the record. The server stores only its own keyed hash of the value, uses it only to choose which copy counts, and does not show it on administrator screens or in exports. See section 5.2 of [`CONTRACTS.md`](../implementation/CONTRACTS.md).

Supported local document extraction transfers bytes through a private bounded worker path and publishes only validated numerical components after association with an observed request. Extracted document-text tokens are non-additive and remain separate from ordinary input/output tokens, provider processing and electricity, carbon or water estimates. Missing extraction, OCR, rendering, retrieval and provider-processing evidence remains explicit.

## Who sees organization data

- Administrators see organization totals and aggregate figures only (owner decision of 17 and 18 October 2026): requests per day, a table by tool and model with requests, the number of distinct people and electricity, carbon and water, how many people used AI, the median and average requests per person, the most active person's request count without a name, and how many people fall in each request band. They never see usage next to a name, email, member id or browser, and never a request list per person. The server enforces this: it has no per-person request endpoint and rejects a `user_id` filter on summaries, breakdowns, exports and recalculations. For access management administrators see each member's work email, role, number of browsers and status, and each browser's connected-since date and status. The deletion preview for one person says what will be deleted without counting that person's records. Health shows counts only. Aggregates are shown for any number of people, so in a very small organization (for example one or two people) they can reveal one person's usage.
- Members see their own figures. Organization totals are shared with members only when an administrator turns sharing on in the admin Policies (`company_sharing`, stored as `threshold` when on). Sharing is off for a new organization (`disabled`), and members then get no organization totals. While sharing is on, members see the totals and their day, tool and model splits whatever the group size. There is no minimum group size and no suppression of small groups, so in a small team the totals can reveal one person's usage.
- The service operator uses a separate address, sees the organization's name, domain, plan, member count and status, and does not receive prompt or answer content.

Administrator access is checked on the server and recorded in the audit log.

## Retention

- Usage records are kept until an administrator deletes them. In the admin Policies an administrator can choose a shorter period of 24, 12, 6 or 3 months. The organization's service plan can set a maximum period; a plan change that shortens it waits until an administrator acknowledges it.
- Records of earlier messages read from chats opened after connecting are kept until an administrator deletes them.
- The same defaults apply to self-hosted servers.
- Connection IP addresses are no longer collected (owner decision of 17 and 18 October 2026). The texts here describe this default; an operator setting can switch the collection back on, which first needs updated privacy texts, a new member consent text in the extension and, in Germany, a works agreement (CONTRACTS section 8). Addresses stored before 18 October 2026 are not shown to anyone and stay in the database only until the operator, after the owner confirms it, deletes all of them with `python -m aift.maintenance purge-network-observations --confirm`. Deleting a person still deletes that person's stored addresses.
- Rate limiting keeps only a keyed hash (HMAC) of the connection's address with the times of recent requests, deleted one day after the last request.
- The extension's Settings show the organization's current usage retention.

Copies of exports that were already downloaded cannot be recalled. Records kept only in a browser stay there until the person erases them or the browser's storage is lost; the organization's policy does not delete them.

## Deletion and exports

Administrators see a preview before deletion: for a date range, the affected records and their contribution dates; for one person, what will be deleted, without counts or the date range of that person's records. Deleting records needs a fresh email code. Deletion jobs and the deletion journal prevent an older database restore or a delayed upload from a browser from bringing erased records back. When a browser reconnects, it fetches the deletion instructions it missed, checks their Ed25519 signature and applies them to the organization records it holds.

After a person's organization records are erased in full, the browser keeps a marker so that nothing from that membership is recorded again. A full Erase all records in Personal mode marks such a leftover marker for review but does not remove it. It is removed only when the person connects again and the server issues credentials for that same membership, which confirms that the membership is active and was not deleted. If the server refuses the connection, is unreachable or starts a new membership, the marker stays. Markers of erased date ranges and single records always stay, so erased records cannot come back (owner decision of 20 October 2026).

Exports are organization summary reports without per-person records. They are created by administrators, can be downloaded only by the administrator who created them and expire after 24 hours. An export that is not yet downloaded is no longer offered after a deletion or a retention change. A downloaded copy is controlled by its recipient.

## Authentication and mail

Website and operator sessions use email sign-in codes, protected cookies, CSRF validation and role checks. Administrator and operator sessions end at sign-out and after at most 7 days. The deployment configures its own transactional mail provider and must verify sender, delivery, tracking and privacy settings. Local FakeMail tests do not establish live delivery privacy.

Report a suspected privacy or security defect privately as described in [`SECURITY.md`](../../SECURITY.md). Do not include employee content, credentials, authenticated captures, real files, raw IPs or private hostnames.
